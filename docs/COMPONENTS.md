# Components

The component library: which component covers each need on a page, the rules for using it, and its wording. Every agent doing UI work reads this first (AGENTS.md, Working rules).

Every page is built from the shared library: `OaksWeb.CoreComponents`, `OaksWeb.DesignComponents` and the layout. Each component is shown in the dev-only gallery at `/dev/components`. A page never builds its own version of something the library covers: no local helpers, no page CSS that restyles it, no copies. (Jeff, 2026-11-21, decision 8f6b: five page agents working in parallel each built their own widths, name helpers, buttons and dialogs, and the site came out inconsistent.)

| Need | Use |
|------|-----|
| A page and its width | `<.page width="column\|read\|form\|frame">` (CoreComponents), on every page. One rule picks the width (decision a0ac): `column` (the default, a centred 960px column) for every single-column page (lists, taxon pages, search, a record such as a source, analytics); `read` for prose (articles, about, privacy, help) and `form` for forms that create or edit and the account pages (log in, setup, settings), narrower centred columns at the 720px reading and 760px form measures (item a44d); `frame` (1400px) only for pages that set columns side by side (the source comparison). The title row (with any back link above it) goes in the `:head` slot, which spans the page's width, so its 2px rule runs the column, or on `read` and `form` the measure, centred with the content under it. A `:bleed` slot runs full-width parts straight under the masthead, such as a title page or the taxonomy band. Never a max-w-*/mx-auto wrapper or page CSS that sets a page's width |
| A page's title row | `<.header>` (CoreComponents), on every page, in the page's `:head` after any `<.back>`, on taxon pages too (the band goes in the `:bleed` above). One rule (DESIGN.md, Title Row; item 7838): the title, then `:meta` on the title's line after it (short facts, one entry each, no separators, in this order: the kind word or the record a form edits, counts, a byline and date, `<.status_tag>` or `<.iucn_status>` stamps, links), wrapping under only when the line has no room; `:subtitle` (a sentence) under the line; `:actions` holds only the page's `<.edit_menu>`, gated to editors, at the right on the title's first baseline. A scientific name in the title is `<.sci_name size="display">`, a source's name `<.work_title>`. Never an `<h1>` of the page's own, a `class` that restyles the row, or page CSS for its parts |
| Taxonomy breadcrumb | `<.taxonomy_band ranks={...} current={...} />` (DesignComponents) in the page's `:bleed`, first, on every taxon page (taxonomy, species, hybrid, variety, the source comparison; item 0a43). Pages pass data, never markup: `ranks` from `OaksWeb.TaxonPath.ranks/1` (a species' `Oaks.Species.placement/1`, or a taxon's ancestors), `current` from `OaksWeb.TaxonPath.current/1` or the current taxon as a step; the band sets rank words and names itself. Never a breadcrumb of the page's own, negative margins or page CSS to place the band; `inline` for a wrapping plate away from the taxon's own page |
| A scientific name anywhere | `<.sci_name>` (DesignComponents), on every page, never `<i>` or a page helper; plain-text names (page titles, aria-labels, URLs) use `OaksWeb.SpeciesName`. Genus 400, epithets 600 (`weight="regular"` for names in running text), the hybrid sign, rank words and author roman; an authority stored in the name is split off. **Size by role, never by page CSS:** `size="display"` in a title row, `"headline"` heading a comparison column, `"title"` (18px) for a name that is itself a list entry, `"meta"` (14px, rank word in Archivo) in a metadata line beside one, and no size anywhere else (prose, dialogs, table cells, field values), where it takes the surrounding size; the taxonomy band sets its own 16px voice. **Genus:** `Quercus` in a title row, at a first mention in a dialog or passage, and in lists whose entries stand alone (species list, search, a taxon's species, a picker); `abbreviate` (Q.) after that, in lists under a named taxon or record (parents, hybrids, relatives, varieties, a source's species), in comparison column heads, for the band's current species and for a species' synonyms (species page; a synonym stored in another genus keeps that genus in full); `genus={nil}` above species, for a hybrid's other parent after "with" and for stored values shown as entered. For a taxon record pass `level` (a complex takes Q., the ranks above it none) |
| An editor's actions on a page (Edit, Delete, Create taxon, New species, Add source data…) | `<.edit_menu id=...>` (CoreComponents) in the title row's `:actions`, `:if` the viewer is an editor: one small "Edit" disclosure, each `:item` a link (`navigate`, `href`) or an event (`click`, `values`), with an optional short `note` after its label ("Manage photos… 1 failed"); a destructive item opens the page's `<.modal>`. Never editor buttons of the page's own in the title row |
| An editor's actions on part of a page (a source's data, a row in a list: a sub-taxon, a source) | `<.edit_menu id=... quiet aria_label="Edit <its name>">`, `:if` the viewer is an editor: the same menu with a small text trigger that never makes its line taller (item c13c). Items name their object ("Edit source data", "Delete subsection"). Never icon buttons, hover-revealed buttons or editor buttons in tab strips, rows or empty states; a page-wide action goes in the title row's menu |
| Buttons | `<.button>`: `primary` (the one call to action), `ghost` (the default: Cancel, Close, secondary actions), `danger` (the ink plate: only a dialog's one action that deletes or can't be undone, labelled with what goes, "Delete species"); size `compact`. Never a page class that recolours a button |
| Dialogs and confirmations | `<.modal id=... show on_cancel={JS.push("cancel_x")}>` (CoreComponents), rendered `:if` the page's state is set (item c13c): `:title` in sentence case ("Delete species", "Can't delete source"), the body says what will happen, each `:note` a consequence (the last `<strong>This can't be undone.</strong>`), `:actions` the one action (`variant="danger"` for a delete). The modal draws its one close control itself, first in the actions row: `cancel="Close"` when the dialog only tells. Esc, a click outside and that control run `on_cancel`; focus goes in and comes back. Never a fixed overlay, panel, card or Close button of the page's own |
| Status stamps | `<.status_tag>`; IUCN status through its IUCN variant *(in progress, item 12b4)* |
| Section labels | `<.section_heading>` |
| A centred page's parts: title page, chapter headings, contents list, a featured taxon, a closing list | `<.title_page>` (in the page's `:bleed`), `<.chapter_heading>`, `<.contents>`, `<.specimen>`, `<.colophon>`. A featured taxon with a photo passes `<.specimen photo={Images.first_for_species(species)} photo_label=... photo_navigate=...>`: the photo (with its credit) in the left 40%, the text set left beside it, stacked on phones. Never a photo of the page's own beside it |
| A work's title with a scientific name in it (a source's name) | `<.work_title>` |
| Tables and ruled lists | `<.table>`, `<.list>` |
| Form fields | `<.input>`; a text field's one button on its line (Load beside an observation field) goes in its `:action` slot |
| Picking, ordering and captioning photos (the species page's Add photos and Manage photos dialogs) | `<.photo_picker>` of `<.photo_tile>`s (a checkbox tile with its license or `<.status_tag>` stamp under it), `<.photo_status>` for an import's state (Added, Already added, Adding…, Failed with its error and Retry), `<.photo_credit>`, `<.ruled_notice>` for a consequence the editor confirms with a checkbox before acting, and `<.photo_list>` of `<.photo_row>`s (drag handle, also Up/Down keys; thumbnail; caption field; credit or status; Delete) (DesignComponents). Never a page's own photo grid, drag handle or status line |
| A species' photos | `<.species_photos images={Images.list_for_species(species)} name=...>` (DesignComponents): ready photos only, in the photo viewer (stage with its position, filmstrip, caption and credit, full view with pan and zoom, details dialog), or "No photos yet.". It wraps `photo_viewer/1` (`Heartwood.UI.PhotoViewer`), the viewer shared with gallformers through heartwood_ui: its markup, hook and CSS live in heartwood, and oaks themes it only through its `--pv-*` properties, in one adapter block (`.oc-photos`). A fix to the viewer is made in heartwood. Pages use `<.species_photos>`, never `photo_viewer/1` directly or a carousel of their own |
| A taxon's photos beside its text (the species page) | `<.photo_columns>` (DesignComponents): `:photos` (a `<.species_photos>`) in a 300px sticky column on the left (240px under 1180px), the text in the rest; on phones one column, the text first, then the photos. The page takes `width="frame"`. Never a grid of the page's own |
| Text by source in tabs (the species page's source text) | `<.source_tabs id=... selected=... on_select=...>` (DesignComponents): one `:tab` per source in the context's order, the open one with its one icon link (`original`, the source's own page, else `about`, its page here); `:action`s at the strip's right end (the quiet `<.edit_menu>` for the open source, then Compare); one `:field` per nonempty field, its text set as that source's prose (`<div class="oc-prose">`), and "No text from {source} yet." when there is none. Never "preferred", a "Data from …" header or tabs of the page's own |
| Rows of names, links or works under a taxon (varieties, hybrids, external links, sources) | `<.ruled_rows>` (DesignComponents): rows on hairlines in three columns (two under 1180px, one on phones), or `columns={1}`; a `:row` with `href` or `navigate` is one link, with an optional `note` (a link's site). A taxon's hybrids are `<.hybrid_rows hybrids=...>` (each name, then "with" its other parent). Never a list or grid of the page's own |
| A run of names (a species' synonyms) | `<.comma_list>` (DesignComponents), each `:item` a `<.sci_name>` |
| A taxon the Oak Compendium doesn't cover yet | `<.not_covered_notice>` (DesignComponents), under the title row; its inner block follows the bold statement |
| The cite-this-page line | `<.cite_line>` (DesignComponents), last on a taxon page; the site names itself, never a person |
| A taxon's common name in its title row | `<.header>`'s `:common_name` slot (CoreComponents): the name, then the `<.source_mark>` of its source (`patch` opens that source's tab) |
| Back links | `<.back>` |
| Not found and error pages | A LiveView that finds nothing at its address raises `OaksWeb.NotFoundError` (`kind: :species \| :taxon \| :source \| :article`, optional `query` for the search), never renders a not-found state of its own: Phoenix then sends the real 404, `OaksWeb.ErrorHTML`'s page, which is `<.not_found>` (DesignComponents) in the site's masthead and footer. Redirects (a synonym's address) stay redirects. The 403 and 500 are `<.error_notice>` |
| Sources and standing marks | `<.source_mark>`, `<.standing_mark>` |

**When the library doesn't have what you need:** stop. Don't build it into the page. Either add it to the library as its own change, shown in `/dev/components` and reviewed by Jeff before any page uses it, or ask Jeff and work on something else. A component that almost fits is extended in the library, never overridden on the page.

**Enforced:** `OaksWeb.Conformance` (`test/support/conformance.ex`) runs in `mix test`, so in `make done-checks` and in CI, and fails on page-width wrappers, inline styles, daisyUI cards and badges, hand-rolled scientific names, and any growth in `app.css`. Exceptions go in its baseline, `test/support/conformance_baseline.json`, with Jeff's approval. The baseline only shrinks: when a file improves, the test fails until its count is lowered in the same change (`mix heartwood.baseline OaksWeb.Conformance`). Never write the baseline to make a new violation pass.

**Wording:** sentence case for page titles, buttons, menu items and dialog titles ("Species list", "Save changes"); back links read "Back to <place>" in lower case ("Back to sources"); create actions read "New <thing>" in menus and titles, and the form's submit button names the act ("Create source", "Save changes").

Keep this table current: a change that adds or replaces a component updates its row in the same commit.
