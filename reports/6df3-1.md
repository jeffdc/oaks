## How it was built

### Design notes

The whole Mix.Tasks.SmokeTest module is wrapped in if Code.ensure_loaded?(Req) do ... end, the usual Elixir pattern for code that depends on an optional dependency. Req is declared only: [:dev, :test], runtime: false; in dev and test it is on the code path at compile time, so the module compiles as before, and in prod it is skipped entirely, so there is no undefined-function warning and no half-working task (MIX_ENV=prod mix smoke_test reports the task as not found rather than crashing). The smoke test only ever runs from CI's deploy workflow (smoke-test job, dev env in the nix shell) and from local checkouts, never inside a release, so nothing that uses it today loses it. Apart from the guard and a comment, the diff is indentation, plus mix format splitting one now-too-long if line in check_health/1. Rejected: making Req a prod dependency (what gallformers does, but gallformers uses Req in prod code; here it would add Req, Finch and Mint to the Docker build and release for no runtime use); @compile {:no_warn_undefined, Req} (hides the warning but leaves a prod module that would fail at Application.ensure_all_started(:req)); excluding lib/mix from prod via elixirc_paths (needs the file moved out of lib or a fragile per-path list, and Jeff's rules rule out moving files without asking). Verified: MIX_ENV=prod mix compile --force --warnings-as-errors is clean; mix help smoke_test works in dev; mix smoke_test https://oakcompendium.org passes 15/15; mix precommit passes (677 tests).
