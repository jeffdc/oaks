## What was built

### Summary

Search results take the shared title row: a visible Results for “query” title, the counts as meta with zero counts hidden (a total only beside two or more kinds), and Add Species as the editor's action. A species found through one of its synonyms now says so after its name (via Q. candida Steud.), from a new Oaks.Search.synonym_matches/2 with the public API unchanged. Every result row keeps its details beside the name on desktop and puts them under the name on phones, the same on every row. Section labels and source names now come from the library, and a long typed query no longer widens the page.

### UI tour

1. Open localhost:4460/search?q=alba logged out at full width: the title reads Results for “alba” with 1 taxon, 8 species, 9 total under it (no 0 sources), on the 2px rule.
2. In the Species list, Quercus floribunda reads via Q. dealbata Royle and the hybrids read via Q. alba × macrocarpa and so on beside the name; Quercus alba itself has no note; sect. names stay at the right.
3. Open /search?q=candida: 1 species, no total; Quercus alba L. with via Q. candida Steud.
4. Narrow the window to phone width (about 390px): every row has its name on one line and its details (via note, then sect.) on the line under it; the Albae taxon row puts 5 species under its name the same way.
5. Open /search?q=Lobatae: 1 taxon only, no total. Open /search?q=zzqx: the title with no counts and the no-results text.
6. Log in (Log in as dev user) and open /search?q=alba: Add Species stands at the right level with the title; at phone width it drops under the counts at the left edge.
7. Open /search: the Search title and the help text as before, no Add Species.

## How it was built

### Design notes

Title row: search results now use CoreComponents.header in the page's :head, as every other page does (626c's contract, Jeff's decision efc6). The title is Results for “query”; the empty page keeps its Search title. The counts are :meta entries in the section order (taxa, sources, species), each shown only when non-zero, with a strong total only when two or more kinds were found (a total equal to its one count says nothing); nothing is found, no meta at all. Add Species is the editor-only :actions, a regular button as a list's create action. The counts bar, its separators and the sr-only h1 are gone with their CSS.

Synonym note: Oaks.Search matches species with a LIKE on the raw synonyms JSON, so it never knew which synonym hit. I added Oaks.Search.synonym_matches/2, which takes search/2's species and the query, loads id, name and synonyms for those ids in one query, leaves out any species whose own name contains the query, and returns the first synonym containing it (same case-insensitive substring test) as %{name, author}. Strings keep their authority in the name (sci_name splits it); object synonyms carry author apart. A string joining several names with = (nine hybrids, bug cb93) is passed over, from the finish review: set whole it broke the italic rule. I kept it out of search/2 so the public /api/v1/search JSON doesn't gain a field without Jeff's say; the cost is one small query by id. The row shows "via" and the synonym as sci_name abbreviated at meta size (Q. candida Steud., decision 3623's synonym form).

Rows: one local result_row component for taxa, sources and species: the name (inner block), then a details span holding the optional note and the meta. On desktop the details sit beside the name with the meta pushed right (margin-left auto), so the via note reads next to the name it explains; at 760px and under the row becomes a column and every row's details sit on one line under the name, which removes the old flex-wrap that wrapped some rows and not others depending on name length. Section labels became the library section_heading (the page's own copy of it is gone), a source's name work_title, and taxa pass level to sci_name instead of the genus/abbreviate pair.

Library: the title row's h1 gets overflow-wrap: break-word, found in verification when a long unbroken query widened the page to 579px at 390. app.css budget 3050 to 3021.

Rejected: putting the via note in the right-hand meta (too far from the name on desktop); a grid with :has for the phone layout (more CSS for the same result); adding matched_synonym to search/2's results (changes the public API). Finish review: three fixes proposed; the garbled-synonym one applied, dropping the strong total and rewording the no-results line declined (the total's strong is 626c's contract, copy is Jeff's).

Verified in Playwright at 1440 and 390, logged out and logged in as the dev user: /search, ?q=alba, ?q=candida, ?q=Lobatae, ?q=quercus (taxa, a source, a species), ?q=zzqx and a 33-letter query; no horizontal overflow at either width; typing in the masthead search patches to the new results with the title and note. Tests: title, hidden zero counts and the total rule, no meta for no results, the editor-only action, the synonym note and its absence on an own-name match, and synonym_matches/2 cases (string, object with author, own name, common name, joined string).
