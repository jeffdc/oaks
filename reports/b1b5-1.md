## How it was built

### Design notes

Approach: copy per run, as Jeff approved on 2026-11-21. The test alias is now [&isolate_test_db/1, "ecto.create --quiet", "ecto.migrate --quiet", "test"]. isolate_test_db/1 reads Oaks.Repo's :database from the loaded config as the template, makes _build/test/test_dbs, sweeps files there older than a day (killed runs never reach at_exit), removes any files left under this run's name (OS pid reuse), copies the template plus its -wal if present and non-empty, and puts the copy's path back into Oaks.Repo's env with persistent: true. ecto.create is then a no-op and ecto.migrate applies any migrations newer than the template. System.at_exit removes the copy, -wal and -shm; Kernel.CLI runs every at_exit hook even after mix test's own failure hook, so failing runs clean up too.
Shape: about 45 lines in mix.exs (the alias function and two helpers), a comment above database: in config/test.exs, comment-only Makefile changes, one added CLAUDE.md bullet, one CONTRIBUTING.md sentence (I joined that paragraph onto one line per Jeff's no-hard-wrap rule). Nothing else resets the env: runtime.exs sets Oaks.Repo only in prod, and mix precommit runs the test alias (confirmed by watching a copy appear during precommit). The CI workflow, test_helper.exs, data_case.ex, the ignore file and test_seeds.sql are untouched.
Rejected: a docs-only one-runner limit (Jeff chose a fix); MIX_TEST_PARTITION in the database path (two bare runs still share one file, and make test-db's rm still hits a live run); copies under priv/ (make test-db's rm -f priv/oaks_test.sqlite* would reach them); making make test-db atomic (documented one-at-a-time instead).
Not exercised: the missing-template branch, because testing it needs deleting priv/oaks_test.sqlite outside make test-db.
Verification, in this worktree:
- Baseline before the change: two concurrent mix test runs gave 69 and 74 failures of 677 tests, all Exqlite "Database busy".
- After: two concurrent runs, three rounds: 0 and 0 failures each round (polling showed both copies present at once).
- make test-db while mix test --repeat-until-failure 6 was running: the passes that overlapped the rebuild all passed with 0 failures; a later pass hit 1 unrelated failure from in-memory LoginLimiter state carried across passes in one VM (filed as bug 0e05). A plain mix test afterwards: 0 failures.
- MIX_TEST_PARTITION=1 and =2 with --partitions 2, concurrently: 304 and 373 tests (11 and 1 doctests), 0 failures each.
- _build/test/test_dbs/ was empty after every passing run, after a deliberately failing run (exit 2; that test saw its copy under test_dbs with 5 seeded species), and after mix precommit.
- priv/oaks_test.sqlite got no new -wal or -shm from any run after the change and still has 5 species.
