## How it was built

### Design notes

The setup controller renders the done page in the same request that starts the session, so conn.assigns.current_scope still held the logged-out scope fetch_current_scope_for_user set at the start. UserAuth.put_new_session now assigns Scope.for_user(user) after creating the session, so any page rendered straight after it (setup done, and the password change page, where it is the same user) gets the logged-in shell. I fixed it in put_new_session rather than in the controller so the session and the scope can't disagree; the setup test asserts the Editor menu is present and the Log in link absent. Checked by test, not in the browser: reaching the page needs a setup link and a TOTP code.
