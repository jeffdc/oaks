## How it was built

### Design notes

Approach: a bridge restyle of four V1 page bodies (home, taxonomy, taxon form, search) onto DESIGN.md, keeping each page's structure, ids, phx bindings and test hooks. The work is in the four LiveView templates plus two app.css blocks this item owns: the taxonomy sub-block of Card Utilities (rewritten as "Taxonomy pages (item 58ef)") and the Search Results section. Where a shared component fit with a cheap template swap I used it: DesignComponents.taxonomy_band, CoreComponents.header, button, back and the oc-modal classes. Tailwind token utilities (border-rule, text-ink-3, font-frame, gap-s3) carry home's rows, since home has no CSS section of its own.

Taxonomy: the gradient header box and V1 breadcrumb became the ochre band and a title row. The band component sits at the top of the page body. The layout has no slot above the frame and layouts are shared, so the band is pulled to the window edges with negative margins equal to the page gutters, and past the 1400px frame by a border-image outset. That outset is painted overflow, so it never scrolls sideways (idea 84c2 proposes a proper layout slot). The title row is the header component: the italic display name, a "Level · N species" subtitle in lining figures, and the editor's Create Taxon / Edit / Delete as compact outlined buttons. The About section, sub-taxa and species are plain sections on section labels with no inset, so they align to the frame. Sub-taxa and species are ruled index columns: CSS columns reading down, each name on a hairline, Quercus at 400 and the epithet at 600, hybrid signs roman, authorities in ink-3 serif, counts in Archivo lining figures. A row's editor actions are 28px outlined ink squares laid over its count on hover or focus-within, so they take no room from the names; on hover:none devices they are in the flow and always visible. V1 showed them on hover only, so touch and keyboard users could not reach them. The delete dialog uses the oc-modal classes, with an ink-plate confirm and no red. Empty states are italic ink-3 lines, with no icons or amber.

Home: left-aligned on the frame. The h1 title row carries the counts as its subtitle, and from 1024px there are two columns (actions and featured species left, data sources right), so the short lists don't leave half the frame empty. Rows are on hairlines; the icon tiles, white boxes and chevrons are gone, and the shuffle icon is a "Show another" compact button.

Search: the counts bar is the title row (hairline separators, lining figures, an sr-only h1). Section labels are DESIGN.md's. Result rows lose their icon tiles; their names are set by the botanical rules and their meta sits at the right. The lists are capped at 56rem so meta stays near its name, while the title rule runs the frame. An empty query now shows a Search title and a line on how to search; no-results drops the quotation marks (the Verbatim Rule).

Taxon form: the back component, title row (name italic), sections on labels, the read-only level as plain text with the system hint, Cancel as a ghost button, and submit as the primary ochre button.

Shared classes: the four pages no longer use fe6d's .edit-content-btn, .create-taxon-btn or .action-btn*, so no page overrides of them were needed. One page-scoped override of the shared band: the current taxon's rank word is set roman (.taxonomy-page-band [aria-current] .oc-band-rk), since the component's current slot makes everything in it italic.

Rejected: a grid of cards with the boxes removed (it reads row-wise, not like an index); a reserved slot for the row actions (it wrapped names in narrow columns); text Edit/Delete buttons on rows (too wide); the band inside the frame without bleed (it read as a box); an outlined Primary tag (b4f7's decision 35cc settles it as an ink plate).
