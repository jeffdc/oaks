## What was built

### Summary

Oaks.Markdown now strips style attributes from every tag (MDEx's default allowlist kept them on code, div, pre and span), so stored content can't set its own colours. The Markdown guide's inline HTML example drops the red span and says inline styles are removed.

### UI tour

1. Open /help/markdown: the Inline HTML section no longer shows red 'colored text', and its description says inline styles are removed.
2. In any markdown field's Preview tab, type <span style="color: red;">x</span>: x renders in the normal text colour.

## How it was built

### Design notes

The sanitize options are a compile-time module attribute: MDEx.Document.default_sanitize_options() with "style" deleted from every tag_attributes entry, so it covers whatever tags MDEx's defaults allow it on rather than a hard-coded list (generic_attributes never included style). Every markdown render on the site goes through Oaks.Markdown.render_html/1, so this is the one place. Tests cover style on seven tags and the help page example; the page was not looked at in a browser.
