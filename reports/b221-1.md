## What was built

### Summary

make dev BRANCH=<name> PORT=<port> serves a branch that lives in another worktree (the integration branch, say) from one command Jeff can leave running in a tmux pane with no background time limit. scripts/dev-branch finds the worktree holding the branch or creates one under .claude/worktrees/<branch>, copies the dev database in with sqlite3 .backup when missing, runs make setup and pending migrations, and serves on PORT (default 4444). Plain make dev is unchanged. config/dev.exs reads PORT (the same line the integration branch has, so the two merge cleanly), and CLAUDE.md lists the new form.

### UI tour

1. In the main checkout, run make dev BRANCH=6b12-site-shell PORT=4460 in a tmux pane: it reports the worktree it uses and serves the integration branch at localhost:4460.
2. Run make dev BRANCH=<a branch with no worktree> PORT=4465: it creates .claude/worktrees/<branch>, copies the dev database in, and serves it.
3. Run make dev with no BRANCH: the server starts in the main checkout on 4444 as before.

## How it was built

### Design notes

The branch logic lives in a small bash script (scripts/dev-branch, in the style of scripts/check-toolchain) and make only chooses between the old recipe and the script, so plain make dev is untouched and the script can be run directly. A worktree is found from git worktree list --porcelain because git allows a branch in only one worktree; a missing one is created under .claude/worktrees/<branch>, where agent worktrees already live, from the local branch or else tracking origin. The dev database is copied with sqlite3 .backup (safe while the main server holds it open) only when the worktree has none, so a preview never writes Jeff's real dev database and a later run keeps the preview's data. The server runs in the foreground with exec so it lives in a terminal or tmux pane, where no agent time limit applies; merges into the branch happen in that same directory and Phoenix's code reloader picks them up. The PORT line in config/dev.exs is copied verbatim from the integration branch so the two branches merge without conflict. Tested both paths: the integration branch's existing worktree served on 4464, and a branch with no worktree (backlog-fixes) got a new worktree, a database copy and a server on 4465 in about 28 seconds; the test worktree was then removed. Rejected: switching the main checkout to the branch (git refuses while another worktree has it) and a separate make preview target (Jeff asked to extend make dev).
