## How it was built

### Design notes

Fixtures follow the gallformers pattern and the existing AccountsFixtures/AnalyticsFixtures conventions: one Oaks.<Context>Fixtures module per context, attrs |> Map.new() merged over defaults, a unique name from System.unique_integer([:positive]), and the insert goes through the context's create function so the real changeset (JsonList casting, the × hybrid-flag check, and 4c78's trimming and URL validation once it lands) runs. Defaults avoid URLs and untrimmed values so 4c78's changes can't break them. Elixir lists are encoded for the JSON-list fields (species relationship lists and synonyms, local_names); articles already accept tag lists. taxon_fixture takes a %Taxon{} parent and stores its name, and taxon_tree_fixture builds a subgenus/section/subsection chain; fixtures never create subgenus Quercus or Lobatae, which the seeds keep.

Each test file builds its own world in setup (never setup_all or module attributes, so inserts stay in the sandbox). Files that relied on the seeded shape (merge, references, taxonomy, species detail/list, taxonomy live) rebuild it with a per-test suffix: alba#{n}, ×bebbiana#{n} with parents alba#{n} x macrocarpa, a subgenus and section sharing the name Quercus#{n} so the same-name rename case is still covered. I rejected a shared oak-world fixture: each file needs a different shape and a shared one would recouple files the way the seeds did. Assertions moved to ids/names of created rows, has_element? on stream ids or scoped elements (a source card, a taxon card) instead of whole-page substrings like =~ "2", Context.count() for whole-table numbers, and before/after differences for /api/v1/stats. Synonym lookups use suffixed epithets, because the extra-seed check showed a seeded "alba var. repanda" would otherwise win the tie on lowest id. schema_test became insert-and-read-back round trips, Import.Metadata through Repo.insert!.

The work landed in five green commits, one table at a time (fixtures; articles; species and species_sources; non-root taxa and import_metadata; remaining sources tests plus docs), each dropping the seed rows in the same commit as the last test that read them. I checked each step by emptying the next table in the test DB with sqlite3 and running the suite. Tests now create sources, taxa and articles freely, so nothing pins seed ids; the grep for get_source(N), /sources/N, /taxonomy/N/, get_taxon_by_id(N) and species_id: N in test/ is empty.
