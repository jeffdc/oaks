## What was built

### Summary

daisyUI is gone (plugin, theme, vendor files) along with the V1 tokens and utilities in app.css. The last V1 uses now use library components: <.input> for the species list fields and <.section_heading> on the forms, source, merge and taxon pages. Prose moved into the system as .oc-prose. app.css keeps only each page's own layout CSS: 2,687 lines down to 2,069. Pages look the same, except that the species list fields are now the system field.

## How it was built

### Design notes

Inventory first: every class app.css defines was checked against lib/oaks_web and assets/js, and every rendered page (logged out and in) was scanned for daisyUI class tokens. daisyUI was only still doing work in two places: the species list's input and selects, and the .card wrappers on the species, article and source forms. The rest of the daisyUI output was emitted because words like list, table or status appear in the source text, and styled nothing.

Removed: the daisyUI plugin, theme and both vendor files; the V1 @theme aliases (forest, oak-brown, acorn, bark, stone/gray/zinc, zeroed radius and shadow scales) and the :root semantic aliases, none of which had a use left; the card, badge, pill-tag and section-title utilities, the daisyUI field overrides, the forest-link fix, the taxonomy note class and the justify-between section-title hack.

Moved: the prose block into components.css as .oc-prose (eight pages and the markdown preview use it), and LiveView's display: contents wrapper rule into base.css. The last V1 uses went onto library components: <.input> for the species list fields, <.section_heading> wherever an h2.section-title stood (forms, source page, merge page, taxon page, with the taxon's updated date as the heading's note). The article and source forms' section stack became a one-column grid so their sections keep the spacing daisyUI's flex cards gave them. The articles tag filter, which no component covers, became a page class with its stamp look and aria-current for the current tag, dropping its two inline styles. The merge spinner was renamed merge-spinner so it no longer shares daisyUI's name.

Kept: each page's own layout CSS, already on the system tokens, because no component covers it; an idea is filed for turning its repeated patterns into components. Moving it to a system file would only have hidden the line count.

Checked with before and after full-page screenshots of 44 pages at 1440 and 390, pixel-compared: everything matches except the species list fields (now the system field) and the home page's random featured species.
