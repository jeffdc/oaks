## What was built

### Summary

IUCN status shows its Red List category colour again (decision 5604): one DesignComponents.iucn_status stamp, filled with the category's conventional colour, code always shown, ink outline and square corners kept, category in the title and for screen readers; used on the species page title row and the species list rows. DESIGN.md adds The IUCN Exception with the colour table and contrast ratios.

### UI tour

1. Open http://localhost:4461/species: each row ends in a square stamp with its code on its Red List colour (LC green, EN orange, DD grey, VU yellow, CR red, NT lime); hover a row and the stamp keeps its colour.
2. Open http://localhost:4461/species/albicaulis: the title row reads Species and a red IUCN CR stamp with paper text; hover it for 'IUCN Red List: Critically Endangered'.
3. Open http://localhost:4461/species/acerifolia (IUCN EN, orange) and http://localhost:4461/species/shumardii (IUCN LC, green).
4. Narrow the window to phone width on /species and /species/acerifolia: the stamps keep code and colour.
5. Open http://localhost:4461/dev/components, Marks section: all nine categories EX to NE in order.
6. Read DESIGN.md, Colors, The IUCN Exception: the table and the rule that the code always shows with the colour.

## How it was built

### Design notes

Approach: one component, DesignComponents.iucn_status/1, built on status_tag/1 so the stamp keeps its type, padding, 1.5px ink outline and square corners, and only the fill (and, on the dark fills, the text colour) changes. The category names live in one map with iucn_category/1, replacing the species list's conservation_title and the species page's conservation_label helpers. The species page shows "IUCN LC"; the list row shows the bare code with "IUCN" sr-only (prefix={false}); both carry the title "IUCN Red List: Least Concern" and an sr-only ": Least Concern", so a screen reader hears "IUCN LC: Least Concern" in both places. A code that isn't a Red List category falls back to the plain stamp with no title.

Colours: the Red List's own category colours, which all pass WCAG AA for the 13px bold code as they stand (ink on EN 7.1, VU 14.3, NT 12.5, LC 8.4, DD 11.8; paper on EW 11.9, CR 4.9). Two tunings only: EX uses ink (#161616) instead of pure black so it sits with the masthead, and NE is paper, i.e. the plain stamp, matching the Red List's white. The ink outline stays on every fill, so the pale VU, NT and DD fills still read as a stamp on paper and on the list row's paper-2 hover. The CSS is .oc-iucn-<code> in assets/css/system/components.css, next to .oc-status.

Rejected: a map of inline styles like V1's species page (not themeable, not in the system CSS); Tailwind tint classes like V1's list (pastel pills, two different colour schemes on two pages); colour without the code, or the code dropped on phones; adding the fills as Tailwind theme tokens (would invite bg-iucn-* elsewhere). The merge page's conservation status stays plain text: it is a field being edited beside a text input, not a status being read.

Docs: DESIGN.md gets "The IUCN Exception" under Colors' named rules (why, Jeff 2026-11-21 decision 5604, the table with contrast, code always with colour, colours mean the category and nothing else), plus matching lines in the Overview, One Field Rule, Press Ink, Status Tag and Don'ts, and iucn-* front-matter colours so the design detector treats them as documented. .impeccable/design.json's Status Tag entry and rules follow. The /dev/components gallery shows all nine.

Checks: component tests for each of the nine (class, code, title, sr label), the no-prefix variant and an unknown code; the list and species page tests assert the LC stamp. Impeccable detector: no findings on the changed lines; live pages only flag the pre-existing italic serif title (botanical convention). Finish review: ship, no material fixes.
