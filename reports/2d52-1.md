## What was built

### Summary

OaksWeb.Plugs.Parsers now answers Plug.Parsers' refusals for the public API (/api/ paths and any path on an api. host) with {"error": ...}, the exception's status and the public API's CORS headers, as it already did for the private API (without CORS). The rest of the site still raises to Phoenix's error pages.

### UI tour

1. No page changes. Open /api/v1/species/search?q=%FF in a browser: a 400 JSON {"error": "The query string is invalid: ..."} instead of an HTML error page.
2. Open /species?q=%FF: still the site's HTML 400 page.

- `make done-checks`: pass, 82.2s

## How it was built

### Design notes

The plug's private_api?/1 became api/1, returning :private, :public or nil, and the public case adds CORS headers through a new OaksWeb.Plugs.CORS.put_cors_headers/1 extracted from the CORS plug (calling the plug itself would also answer an OPTIONS preflight and double-send). The messages are the existing ones, shared by both APIs, since they already read fine for a public caller. Tests in parsers_test.exs cover a bad query string with every accept header, bad JSON, the api. host, and that private refusals still have no CORS headers.
