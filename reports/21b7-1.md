### Summary

The DESIGN.md system is in the app: tokens as Tailwind theme variables (ink, paper, ochre, pencil, rule, font-frame, s1-s8 ...), self-hosted Source Serif 4 / Archivo / Archivo Narrow, a new base on every page (paper ground, serif body with oldstyle figures, pencil links, ochre selection, 3px pencil focus), a new OaksWeb.DesignComponents module (taxonomy band, section heading, source mark, standing marks, status tag, Compare button, other-sources disclosure) and the core components restyled square and flat (button, header, ruled table, list, modal, back, flash, inputs). ### UI tour

1. Run the server (PORT=4445 mix phx.server in this worktree, or as usual) and open /dev/components: the ochre taxonomy band with drawn chevrons on top, the Components title on a 2px ink rule, then Marks, Buttons, List, Field marks, Form fields and Notices, all square, flat and ink on paper.

5. Click 'Open a dialog': a square paper panel with a 2px ink border over an ink wash, Close with an Esc hint; Esc closes it.
6. Narrow the window to phone width: the band becomes one line scrolled to Q. shumardii with a fade on the left, and the field-marks table becomes one labelled block per trait.
7. Open /, /list, /species/shumardii, /taxonomy/Quercus, /sources and /about: the old green header, cards and badges are unchanged, now on the paper ground with Source Serif 4 text and pencil links (see the About page's links); numbers in running text use oldstyle figures.
8. Log in as the dev user and open /species/shumardii/edit: the form fields are the new square white fields with Archivo labels inside the old cards.

## How it was built

### Design notes

Approach: add the DESIGN.md system beside the V1 look rather than replacing it, so pages can move over one at a time (Jeff's piecemeal rollout). Everything new lives in assets/css/system/ (tokens.css, fonts.css, base.css, components.css), imported from app.css right after Tailwind, mirroring gallformers' assets/css/system layout.

Tokens: the DESIGN.md frontmatter becomes a Tailwind v4 @theme block, so each token is both a CSS variable and a utility: colors ink, ink-2, ink-3, paper, paper-2, ochre, pencil, rule, rule-strong (text-ink, bg-paper, border-rule ...); fonts --font-serif (re-pointed from Georgia to Source Serif 4, so V1 headings follow), --font-frame (Archivo), --font-narrow (Archivo Narrow); spacing s1-s8 (p-s4, gap-s5, mt-s7); --container-frame 1400px (max-w-frame). No name collides with the forest/oak tokens. oc.css's --ochre-deep was left out (unused, and DESIGN.md forbids ochre as text).

Fonts: self-hosted in priv/static/fonts/<family>/ with OFL licences, because the CSP only allows fonts from 'self'. The Google Fonts and fontsource builds of Source Serif 4 strip the onum/lnum features, which would silently break the oldstyle running figures DESIGN.md asks for, so Source Serif 4 is subset with pyftsubset from Adobe's 4.005 variable fonts (wght 200-900 plus opsz 8-60, so display sizes get the display optical size), latin and latin-ext files split by unicode-range. Archivo and Archivo Narrow are the fontsource variable wght builds. Only the serif roman latin file is preloaded; Archivo isn't used on every page until the masthead (3248).

Layering: the V1 CSS is unlayered, and unlayered rules beat any @layer. So the new base (body, links, focus, selection, figures, q quotes, kbd, reduced motion) replaces V1's own base section and sits in @layer base, under the V1 component CSS, which keeps the old cards, badges and green header intact. New components are in @layer components with an oc- class prefix, so they never meet V1 classes and a utility passed in class still wins. The V1 :root text/background variables and daisyUI base-100/200/content are aliased to paper/ink so old pages share the new ground and inks; borders, white cards and the forest primary were left alone. daisyUI stays (cards and badges depend on it); its removal is captured as an idea.

Components: the generic Phoenix pieces stay in CoreComponents and are restyled (button ghost/primary/compact, header as the title row on a 2px rule, table as the ruled table with row_header and voice columns and an opt-in stack mode that turns rows into labelled blocks on phones, list as a ruled dl, modal as a square bordered panel with a Close/Esc button, back with a drawn chevron, flash as a paper notice or a reversed ink plate, inputs as the white 1.5px field). Scientific-name italics are left to callers (<i>), since hybrid formulas mix roman and italic.

States without colour: errors are an ink plate (flash), a 2px ink border with aria-invalid, and a drawn ring-and-bar mark, since DESIGN.md has no error colour. Motion: show/hide and the modal now fade only; the comparison slide stays the one authored motion. Focus: pencil everywhere, ink on the ochre band and paper inside .dark-bg, where pencil falls under 3:1.

Review: a dev-only gallery at /dev/components (dev_routes-gated LiveView, no app layout) renders every component with real prototype content; it is where the detector and the impeccable finish review looked.
