## How it was built

### Design notes

The shell is two function components in OaksWeb.Layouts, site_header/1 and site_footer/1, called from app.html.heex with the skip link, the page frame (main#main.oc-page) and the flash group. Both read assigns[:current_scope] and a path tolerantly: LiveViews pass @current_path from the ActiveNav hook, and controller pages (login, security settings) fall back to conn.request_path, so every page gets the same masthead with the right current item. I kept them in Layouts rather than DesignComponents because the layout is their only caller; DesignComponents holds the page-level pieces.

The CSS is a new assets/css/system/shell.css in @layer components with oc- classes, built from oc.css .mast/.nav/.search/footer.site/.who and the DESIGN.md frontmatter, using only tokens (paper alphas are color-mix of --color-paper, so the detector sees no off-palette colours). One deliberate refinement over the prototype: nav items stretch to the masthead's full height, so the 3px ochre current underline is the masthead's bottom edge rather than floating 2px above it; the focus ring then wraps the label span (paper, 4px off) instead of the 60px-tall item. Focus on ink is paper throughout, the search field rings as a whole via :focus-within, and the caret is paper (the base sets an ink caret, invisible on ink).

Editor marks: there is no editor area yet, so instead of the prototype's Editor nav link I made Editor a nav-voiced <details data-menu> holding the tools that used to sit in the header (Add species, Settings, Log out), with the editor's name in ochre after it. The menu panel is paper with a 1.5px ink border like the band's siblings menu. Esc and click-outside closing, and the "/" hotkey, are document listeners in app.js (CSP forbids inline script), not phx bindings, so they also work on the controller pages; JS.ignore_attributes(["open"]) keeps the menu open across LiveView patches. About stays in the nav for editors.

Layout: one row down to 1025px; at 1024px and under the masthead stacks (mark and editor marks, then full-width search, then the nav on its own scrolling row along the bottom edge), and at 760px the gutters drop to 16px and the "/" hint hides. The prototype wraps at 760, but with the editor marks the one row needs about 960px, so the finish review moved the stack point to 1024. Flash notices (21b7 put them at the top right, over the search) now sit below the masthead, or at the bottom once it stacks. The masthead isn't sticky, like the prototype. Archivo is preloaded now that every page uses it.

Navigation inventory: Species (now /species, with /list a 301 keeping its query string), Taxonomy, Sources, About; Identify waits for its page. Articles, Privacy and the API docs moved to the footer beside the licensing line, plus Log in for logged-out visitors (replacing the Settings gear's role). The About and Privacy page footers stay as page metadata above it. Rejected: putting the editor tools as separate masthead links (too many items for the 60px row), and keeping Articles in the main nav (it isn't in DESIGN.md's nav).

The V1 header, search and skip-link CSS is removed; page bodies keep their V1 look. header_test.exs is rewritten for the new shell (nav order, current item on LiveView and controller pages, editor marks, footer), and the species list test covers /species and the /list redirect. Impeccable's detector is clean on the shell files, and its finish review's fixes are applied in the last commit; DESIGN.md's Navigation now records the editor marks, the stacked masthead and the footer.
