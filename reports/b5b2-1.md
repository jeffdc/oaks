## How it was built

### Design notes

Shape: one bash script in the style of scripts/check-toolchain (ok/FAIL lines, CHECK_UI_ROOT override, non-zero exit). A single awk pass over every .ex and .heex file under lib/oaks_web emits rule, path, line and text for each hit; the script counts them per rule and file and compares the counts with scripts/check-ui.allow. It runs in about 0.3s, and works with both gawk (the Nix shell) and macOS's BSD awk and bash 3.2. Elixir # comment lines and one-line HEEx comments are skipped.

Rules, all line-based so counts are per line: width (outside components/) is a line with both a max-w-* token and mx-auto, or a page-scale token on its own (max-w-3xl..7xl, max-w-screen-*, max-w-prose, max-w-frame), with Tailwind variants counted; dialog widths (max-w-md/lg) and ch measures alone are deliberately left out. style is style="..." or style={...} anywhere, components included, but not style=\" inside an Elixir string (the markdown help text). daisyui is the bare card or badge token or a card-*/badge-* modifier inside a class= value, or as the first word of a string literal of class tokens; page classes that merely contain the word (taxon-card, comparison-preferred-badge) and prose don't match. sci-name (outside components/ and species_name.ex) is a line that opens an <i> or <em> whose content up to its closing tag, even lines later, names a taxon (scientific_name, Quercus, "Q. ", .subgenus/.section/.subsection, taxon.name, <.taxon_name, or a call to epithet/band_name/display_name/full_name/sci_html/name_iodata...), an italic class token with such a name on the line, a def clause of a name helper (sci, sci_*, *binomial*, epithet, formula_parts, name_iodata, name_html, name_parts, taxon_name, taxon_display_name, band_name, format_species_name), or a "Q. #{" string. Bare literal epithets (<i>Lobatae</i>) and plain-text names passed to components aren't matched: no way to tell them from other italics without noise. app-css is the line count of assets/css/app.css against the budget line.

Ratchet: counts per file, not line numbers, so unrelated edits don't break the list. Failing on a fall too (not just a hint) keeps the list honest: the allowance is lowered in the same change that improves the file. --baseline writes the file when there is none, and otherwise only lowers counts, drops zeroed entries and keeps comments and a note column, so it can be run freely; adding or raising an entry stays a hand edit Jeff approves.

Rejected: scanning only inside ~H sigils (needs a parser, and the line patterns are already precise), counting helper uses rather than definitions (calls go when the def goes), and flagging "Quercus #{x}" strings (that's a legitimate argument to the coming sci_name component and to page titles). Not covered: page widths set in page CSS (max-width in app.css), which the app.css budget only bounds.

Verified: passes on the tree; in a scratch copy, a new max-w-2xl mx-auto wrapper, an inline style, a card class, <i>{@species.scientific_name}</i> and 10 app.css lines each failed with the offending line; a fifth card in an allowed file failed with all its lines listed; removing a card and shrinking app.css each failed asking for the lower count; --baseline then lowered both, kept a note, and refused to add a new violation or raise the grown one. make done-checks passes.

### Decisions made in the session

Accepting the review ratifies these. To decide one differently, before accepting: `mull decide <id> "..."`

- **0258** scripts/check-ui --baseline writes the allowlist only when there is none; afterwards it only lowers counts and drops entries at zero (keeping comments and notes), and never adds or raises one, so loosening the list is always a visible hand edit
  Why: The check demands lowering whenever a file improves, so agents need an easy way to do it that can't sneak in new allowances
- **4466** The sci-name rule exempts lib/oaks_web/components/ and lib/oaks_web/species_name.ex (OaksWeb.SpeciesName, the shared plain-text name helpers); the style and daisyui rules apply to components too; the width rule covers all of lib/oaks_web outside components, so the hand-copied shell in controllers/error_html.ex is on the allowlist
  Why: Components are where widths and name markup belong; SpeciesName is text, not markup, and the coming sci_name component will build on it
- **5de3** The sci-name rule doesn't flag a component passed a plain-text name (<.sci name={"Quercus #{x}"}>) or plain-text names in page titles and URLs, but does flag the hand-abbreviated genus in a string ("Q. #{...}")
  Why: Passing Quercus-prefixed text could be a legitimate use of the coming sci_name component; abbreviating the genus by hand is one of the inconsistencies a6c7 lists
- **ee1c** The dev component gallery (live/dev_components_live.ex) gets no exemption: its own page wrapper and its <i>Quercus</i> band examples are on the allowlist
  Why: It's a LiveView page like any other; the band examples follow the band component's current 'callers wrap names in <i>' contract and drop out when sci_name lands
