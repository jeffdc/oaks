## How it was built

### Design notes

New module lib/oaks/changeset_helpers.ex (Oaks.ChangesetHelpers), cribbed from gallformers without `use Boundary`, with @specs, and with the redundant second String.trim in the URL check dropped (normalize_url already trims, so the check only special-cases "").

trim_strings/1 reads the schema's persisted fields with __schema__(:fields) and keeps the :string ones, so virtual fields (User.password), arrays (ApiToken.scopes), binaries and integers are never touched. It trims each changed binary and uses put_change, which drops the change when the trimmed value equals the stored one. That is intended: a whitespace-only edit is no edit, so it can't start a taxon rename cascade or stamp content_updated_at. It goes right after cast, before JsonList.cast (JsonList.normalize trims on its own, so the order is safe) and before validations, so length checks see the trimmed value.

validate_url/2 trims, puts https:// in front of a value starting with www., then for a non-empty change requires an http or https scheme and a non-empty host via URI.parse. validate_change only looks at changes, so a legacy non-URL value already stored doesn't block editing a source's other fields. On SpeciesSource it runs before validate_length(:url, max: 1000) so the length is measured on the normalized URL.

empty_strings_to_nil/2 is kept for put_change/change paths; Ecto 3.14's cast already turns blank input into nil through empty_values, which the @doc says.

Wired into Species.changeset, Source.changeset (plus validate_url on url and license_url), SpeciesSource.changeset (plus validate_url on url), Article.changeset and form_changeset, and Taxon.changeset. User.email_changeset and ApiToken.changeset swap update_change(&String.trim/1) for trim_strings, which behaves the same. PageView, Import.Metadata, User.password_changeset and Accounts.change_setup are left alone. Web-layer trims in LiveViews (article tags, taxon links, species merge) are LiveView state cleanup and stay.

Rejected: a field-list trim_strings/2 as the item text said (easy to forget a field; gallformers uses /1), and checking URLs inside the JSON link fields (captured as idea cc6f).

Risk for the merge: Species.Merge (lib/oaks/species/merge.ex, around lines 280-300) inserts new SpeciesSource changesets, so a legacy species_sources.url in production that isn't an http(s) URL would now fail a merge with the URL error. Production should be checked for such rows before merging.

Tests are in one new file, test/oaks/changeset_helpers_test.exs (ExUnit.Case, async, no database): an inline schema covers trimming, the virtual/integer/array skips and the no-change-when-equal case; the gallformers URL cases plus ftp:// and javascript: rejections and an unchanged invalid stored value; empty_strings_to_nil; and pure changeset calls proving each schema is wired. No existing test changed.
