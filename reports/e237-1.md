## What was built

### Summary

Phoenix's plain-text error pages are replaced by standalone Oak Compendium pages for 403, 404 and 500 (OaksWeb.ErrorHTML embeds error_html/*.heex): a minimal ink masthead with the acorn mark linking home, the serif title on the 2px rule with an 'Error 404' status stamp, a sentence of what happened, ochre for the one next step and the prototype footer. The 404 names the address asked for and offers a plain GET search form and the species list; the 403 explains a refused (expired) form; the 500 points home. Go back follows a safe http(s) Referer. No script, no app layout, no CSS file changes; other statuses keep their plain status message.

### UI tour

1. Open the review captures in the scratchpad (/private/tmp/claude-501/-Users-jeff-dev-oaks/645dbf50-1151-4687-9bdc-51e3d8592f94/scratchpad/review/): desktop-404.png shows the ink masthead with the acorn, 'Page not found' on the 2px ink rule with an outlined 'Error 404' stamp at the right, the sentence naming /species/shumardi, the search field with the ochre Search button, then Species list, Home and Go back, and the three-part footer at the bottom.
2. To see the pages live, temporarily set debug_errors: false in config/dev.exs (don't commit it), run PORT=4447 mix phx.server in the worktree, and open http://localhost:4447/species/shumardi-typo: the 404 page, naming that address.
3. Type alba in the search field and press Enter (or click Search): you land on /search?q=alba with results. Back on the 404, click Species list: /list opens.
4. Narrow the window to phone width: the gutters drop to 16px, the stamp stays beside the title, long addresses wrap inside the column and nothing scrolls sideways.
5. Press Tab: the masthead mark gets a paper focus ring, the field and buttons a pencil one. Hover Search: it inverts to ochre text on ink.
6. For the 403, open http://localhost:4447/users/log-in, leave it, restart the server (which invalidates nothing) or edit the page's hidden _csrf_token in devtools to garbage, then submit: 'Request refused' explains the expired form, with Go back as the ochre button, then Log in and Home (desktop-403.png and mobile-403-noref.png show both cases).
7. The 500 is in desktop-500.png and mobile-500.png: 'Something went wrong' with Home as the one ochre button. Put debug_errors back to true when done.
8. After deploy, https://oakcompendium.org/no-such-page shows the real 404.

## How it was built

### Design notes

Approach: port gallformers' error pages (a standalone error_page/1 document, no script, Go back from a safe http(s) Referer) into the DESIGN.md world 21b7 built. OaksWeb.ErrorHTML now embeds error_html/{403,404,500}.html.heex; any other status still falls back to its plain status message (render/2 kept). config's render_errors keeps layout: false, and ErrorJSON is unchanged.

Standalone, not the app layout: on an unmatched route no pipeline runs, so there is no session, flash or current_scope (the app layout reads @flash), a 500's layout data may be what failed, and it keeps e237 independent of 3248, which is building the real masthead in parallel. error_page/1 owns the head (title "<Title> · Oak Compendium", description, favicon, the serif and Archivo preloads, app.css), a minimal ink masthead (the prototype's acorn drawn with fill-ochre/fill-paper classes, Archivo 800 19px "Oak Compendium" linking home, .dark-bg so its focus ring is paper), the page and the prototype footer on a hairline, pinned to the bottom.

The page is the taxon page's title row reused: CoreComponents.header (serif h1 on the 2px ink rule) with DesignComponents.status_tag "Error 404" at its right, instead of a big centred number or an eyebrow over the heading. Then one serif paragraph (68ch, text-pretty), then the ways on as square buttons with ochre only on the one next step: Search on the 404 (a plain GET form to /search?q=, oc-input + primary button, works with no JS), Go back on the 403 when there is a Referer (otherwise Log in), Home on the 500. Species list (/list, which 3248 will redirect), Home and Go back are ghosts; Go back comes last and only appears for an http(s) Referer.

The 404 names the requested path (conn.request_path, HEEx-escaped, Archivo with lining figures, wrap-anywhere) so a typo is visible. The 403 copy is written for the only HTML 403 the app has today, Plug.CSRFProtection's invalid-token error (an expired form): the finish reviewer flagged the first "you don't have permission" copy as naming the wrong problem. The 500 makes no claim that anyone was notified, since no error reporting is configured.

Styling is Tailwind utilities on the 21b7 tokens plus existing oc- components; no new CSS file and no app.css change, so nothing collides with 3248's layout work. Copy uses typographic apostrophes.

Tests: error_html_test.exs rewritten along gallformers' lines (each status's title and content, stylesheet link, home aria-label, footer, no script/style, Go back with and without Referer, javascript:/data:/relative Referers rejected, escaped request path, the 400 fallback), plus two endpoint tests: an unknown address returns this 404 page, and a POST without a CSRF token returns this 403 page.

Preview: dev has debug_errors: true and router.ex belongs to 3248, so rather than a dev route I rendered the pages with a scratch mix run script (real conns with Referers and paths) and served them through Playwright route interception on the dev server's origin, so the real app.css and fonts load. Checked at 1440x900 and 390x844: no horizontal overflow, long paths wrap, focus rings (paper on the masthead, pencil elsewhere), the Search hover inversion, and the search form landing on /search?q=alba.

Impeccable: treated as an extension of the established world (no direction roll, comp or DESIGN.md change). Detector: source scan has one advisory, text-[19px] on the wordmark, which DESIGN.md's masthead prose specifies; URL scans of all pages at both widths are clean after two fixes (a one-word last line on the 500, and the 403 title "Access denied", which the detector read as a bot-challenge page). Finish review: first pass asked for a recapture of the hover state, then a full review returned fix with one material item (the 403 copy); after the fix the verdict pass scored it resolved, disposition ship.

Rejected: a dev_routes preview route (router.ex is 3248's), a CSS file for the masthead/footer (merge risk with 3248 for a stand-in), the gallformers-style centred big status number with a figure, and a "Try again" link on the 500 (could loop on a deterministic error, and re-GETs a failed POST).
