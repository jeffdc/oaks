Look for existing code in the component library (`lib/oaks_web/components/`, with the table in docs/COMPONENTS.md saying which component covers each need), the web helpers (`OaksWeb.SpeciesName`, `OaksWeb.TaxonPath`, `OaksWeb.Params`), the shared utilities (`Oaks.ChangesetHelpers`, `Oaks.JsonList`, `Oaks.Licenses`, `Oaks.Markdown`), the public functions of the contexts the change calls, and heartwood (`deps/heartwood_guardrails/guardrails`).

1. **The component library.** Does a page build its own version of something the library covers: a name, width, title row, button, dialog, stamp, mark, notice or row? Or does it restyle a library component from page CSS? `OaksWeb.Conformance` catches some of this; the rest is yours. A finding blocks.
2. **Heartwood.** Does the change copy or edit code that heartwood holds (the ratchets, retirements, hooks, review scripts, `check-toolchain`) instead of using the dependency? A finding blocks: the fix goes into heartwood. A module copied from gallformers must start with its origin line (gallformers, the path, the commit, what was adapted); a missing one blocks.
3. **AGENTS.md** (CLAUDE.md is the same file) holds rules, not status or plans. Status or plans added to it is a finding that blocks.
