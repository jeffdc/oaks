All `mix test` processes in one checkout share one SQLite file (config/test.exs:64, priv/oaks_test.sqlite). Concurrent runs collide: a deferred transaction's read-to-write upgrade fails immediately with 'Database busy' (no busy_timeout wait), giving 6-18 failures.

The 'Database busy' flake within a single run is already fixed (default_transaction_mode: :immediate in the test/dev/prod Repo config, and Analytics.track_async runs inline when :analytics_async is false). What remains is two runs at once in the same checkout. Fix it one of two ways:

- a per-partition test DB (MIX_TEST_PARTITION in the database path), keeping make test-db and the CI 'Setup test database' step working with it; or
- document "one mix test runner at a time per checkout".

Done when two concurrent mix test runs in one checkout both pass, or the limit is documented in CLAUDE.md's Testing section.

From matter a9a3.
