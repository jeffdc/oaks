One private API endpoint for bulk changes, so data never goes in by hand-run SQL (absorbs e773; Jeff, 2026-11-21, decision e661).

- POST /api/private/v1/import behind a packages:submit token (fbd0's require_api_scope/2).
- Body: JSON shaped like the data model, one key per table (e.g. {"taxa": [...], "names": [...]}), field names matching the Ecto schemas. Records in one body can point at each other by local refs.
- Each record goes through its Ecto changeset; the whole body applies in one transaction or not at all. Errors come back per record (table, index, field, message).
- dry_run: validates and reports what would be created or changed, writes nothing, and returns a token tied to a hash of the exact body. The real call must carry a matching token or it is refused, so agents always dry-run first and can't apply a different body.
- Optional import_id: re-sending an applied import is a no-op.
- Start with the tables that exist when this is built; each model item (c3c8 taxa, 0614 materials, 0f0b facts, 18e8 observations) adds its tables to what the endpoint accepts.
- A short producer note for agents: the JSON shape, local refs, dry run then apply.

No JSON Schema contract, Python validator, staging, diff screen, package undo or audit log (Jeff, 2026-11-21).
