species.external_links has no input on the species form (lib/oaks_web/live/species_form_live.ex), so it can only be changed by editing the DB. It is a TEXT column holding a JSON array of link objects, e.g. {"source": "FNA", "name": "Flora of North America", "url": "https://floranorthamerica.org/Quercus_acerifolia"} (source is optional; the FNA and FEIS links were written by scrapers/external_links/add_fna_links.py and add_feis_links.py). The detail page (species_detail_live.ex, around line 1089) parses it with Species.parse_json_array and adds computed links built from the scientific name via build_external_links; only the stored links are editable.

Decide the editing UX. The proposal is repeatable name + url rows. Validate URLs.

Related, already done: the other JSON list fields (hybrids, closely_related_to, subspecies_varieties, synonyms) normalize comma input and validate array-of-strings with a visible error on save (matter 94ae, commit 9f4ec42; see Oaks.JsonList). external_links values were normalized (NULL vs []) by data migration 20261102180000. Merge unions external_links into the target.

Done when links can be added, edited and removed from the species form, and invalid URLs show an error.
