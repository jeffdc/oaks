The Dockerfile places the hashed binary at tailwind's own default path (_build/tailwind-linux-x64-musl-<version>), which couples it to the package's naming (it changed in 0.5) and only matches on amd64: a local arm64 build (Colima on Apple Silicon) misses it and downloads an unverified linux-arm64-musl binary. Setting ENV MIX_TAILWIND_PATH to the ADDed file, as flake.nix already does for dev and CI, would use it on any platform and fail loudly instead of downloading; check-toolchain's new _build path check would then move to that ENV line.
